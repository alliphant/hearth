Hearth is the house that remembers.

A maternal-presence team of 12 specialists, running over one local LLM, with one Obsidian-friendly markdown vault as the source of truth. They notice, prepare, and — within calibrated boundaries — act. The interrupt budget is your most precious resource; the system is designed to absorb so it can interrupt rarely and well.

What it is

Not an agent. A tool server.

Hearth exposes typed HTTP endpoints that an LLM-driven runtime calls. The runtime today is the SpecialistRuntime — a persona-over- shared-model layer where each specialist is a YAML file, not a process. Hot-reloaded. Capability-gated. Auditable end to end.

Memory

Markdown is forever

The vault at ~/vault-friday/ is the source of truth — people, journals, decisions, clippings, places. SQLite is a derived projection, rebuildable from the vault. Anything you might want to read or edit in five years is a plain file.

Preparation

Ready before you are

Kate's brief lands at 7 AM — birthdays, lapsed contacts, today's events with real ETAs. Iris already knows whether tomorrow fits on the Ioniq 5's charge. Brigid already has dinner picked from what's in the fridge.

Boundaries

Trust is earned, narrowly

A YAML-driven approval gateway gates every external effect. Trust graduates per-recipient, per-domain, after N approvals- without-edits. Edits and denials cost. Sensitive, legal, and first-contact categories never auto-graduate.

The three-loop model

Awareness is fast. Deliberation is thoughtful. Interrupts are rare.

One loop would be too noisy or too quiet. Three loops separate cost: awareness updates state, deliberation batches state into proposals, interrupts only fire when a proposal is worth your attention.

Awareness
continuous · 60s tick

Chokidar watches the vault. Per-specialist handlers diff what's changed since their last run — note mtimes, inbox arrivals, audit-log clusters. No LLM. Just signals.

Deliberation
scheduled · per-specialist slots

At each HH:MM tick, the specialist takes one LLM turn over recent observations + unread inbox + tail of memory.md. Returns a JSON envelope: flags, proposals, interrupts.

Interrupts
only when justified

Specialists route interrupts to Kate by default. Kate absorbs most (logs what she did instead). She promotes the rare ones to you. Calibration shows in the audit log.

Anatomy of a tool call

From "Hey Kate" to vault write.

Every external effect crosses three checkpoints: capability, policy, audit. Reads cross two: capability and audit.

Tiered autonomy

Trust graduates, narrowly.

The gauge fills with category-signature approvals without edits. Edits or denials cost. Sensitive, legal, medical, first-contact, and over-cap categories never auto-graduate regardless of count. The user always approves the graduation itself.

1
ReadVault lookups, audit queries, external read-only feeds.
2a
Write internalVault writes — journal entries, person notes, decisions, places. Reversible; the audit log shows exactly what changed.
2b
Send external, low-stakesText to family, email to a frequent colleague. Defaults to approve; graduates per recipient.
2c
Send external, high-stakesFirst-contact emails, sensitive recipients, novel categories. Approval-only; never auto-graduates.
3
Spend money or commit timeBookings, purchases, calendar invites to others. Approval-required with a cooldown.

Novel bits

The interesting parts.

Things that aren't obvious from the architecture diagram — patterns that fell out of running the system and noticing what was actually hard.

Pattern

Per-turn tool curation

Capability gating decides what a specialist may invoke. Curation decides what the model sees on a given turn. Past ~15 tools, Qwen 3.6 starts emitting empty-args. Iris carried 25 resolved tools uncurated and timed out on every turn until tools_for_chat was set.

Pattern

Kate as router, not forwarder

Every non-Kate-originated interrupt routes to her inbox. She either absorbs (most cases — logs what she did instead) or promotes (rare). The absorb/promote ratio over time is the metric for whether her filtering is well-calibrated.

Pattern

the workstation: the browser escape hatch

Maggie hits a Cloudflare-walled venue calendar. Firecrawl returns empty markdown. Next round: browse_url on the same URL, which wakes the workstation over WoL, spawns a nested KWin + warmed Firefox on a real NVIDIA GPU, pulls the page, tears down, sleeps. The fingerprint passes because the browser is real.

Pattern

Closed-loop self-healing

Mariah scans daily for failed work, drifted patterns, and misaligned configs. Work-failures route back to authors; config-failures escalate to Beatrice, who proposes a YAML or code change. Jasper approves it; the path-allowlisted PR machinery ships it. Detection autonomous; shipping never.

Pattern

Kate learning Jasper's voice

observe_jasper_voice runs as a background batch pass over recent turns. Stylistic observations land in Knowledge/Kate/jasper_style/. Periodically distill_jasper_style rebuilds the profile from bullets + writing corpus. draft_message reads from that profile so the draft sounds like Jasper, not Kate.

Pattern

Maggie's taste graph

MusicKit + Plex listening signal flows into a taste profile. The artist watchlist scores affinity. The venue watchlist stores calendar URLs. add_concert_history writes atomically to both. The morning brief surfaces matched shows only when affinity × proximity × novelty crosses threshold.

Pattern

Canned fallbacks don't re-poison history

When a turn fails, the user sees a real fallback message in the conversation. But is_fallback_message() skips it when rebuilding the LLM context — otherwise the model reads the timeout string as an exemplar reply and parrots it on every later turn.

Pattern

Location is the most privileged data

Three defense-in-depth layers: capability flag, allowlist in privacy.yaml, and redact_for_audit() that rounds coords to 3 decimals and strips street-level addresses. ha_get_my_location audits only zone + confidence, never raw coords.

Pattern

Cross-surface continuity

Threads are keyed by (user, specialist), not surface. The relay creates a new conversation when the most recent activity is >24h old — "morning's chat" and "tonight's chat" are usually different threads. Below 24h, the thread continues across Telegram, web, and (soon) voice.

Memory & vault

Anything you might read in five years is markdown.

Vault notes, audit log, system prompts, persona files, specialist memory — all plain markdown with YAML frontmatter. SQLite holds derived projections (fast queries, FTS5, graph edges, idempotency keys). If SQLite corrupts tomorrow, bun run ingestor:rebuild walks the vault and reprojects.

Derived projection

data/hearth.db (SQLite WAL)

One file, shared by orchestrator + ingestor + scheduler. Tables: people, journal_entries, clippings, places, graph_edges, audit_log, chunks_fts (FTS5), approvals, proposals, scheduled_tasks, briefs, conversations, messages, process_misses.

Scalability vectors

Where the design has room to grow as the household grows.

Multi-user

Per-user voice & privacy

Brigid's per-user diet store (users/<name>/brigid/**) is the template. The next move: a per-user knowledge_scope overlay so each household member has their own private journal and finance namespace. Conversations stay keyed by (user_id, specialist_id).

Cross-user privacy

Kate & Cassandra as sensitivity gates

A request from User B that touches User A's data routes through Kate (sensitivity classifier) and Cassandra (policy check) before any specialist sees it. Financials, medical, PII, confidential decisions → denied or summarized to public shape. The audit log captures every cross-user query for inspection.

Trend & taste mining

Maggie's signal stack, generalized

The taste-graph / watchlist / heavy-rotation pattern fits any preference domain. Vivian's spending trends. Eleanor's planting success rates. Anya's pet-health baselines. Each becomes a per-specialist "taste profile" that the morning brief draws from when novelty × relevance crosses threshold.

Voice imitation, generalized

Each specialist learns the user they speak to

Kate's observe → distill → draft loop is per-user today. With multi-user, each specialist maintains a per-user style profile and drafts in the addressed user's voice — your Brigid sounds like you when she's drafting a follow-up to a recipe; your partner's Brigid sounds like them.

Browser surface, fleet

One agentd port, many warmed profiles

Today Maggie is the only browser-using specialist; v1 agentd serializes sessions. v2 lifts that by spawning parallel nested KWin compositors per agent profile. The contract — one auth token, one port, per-agent warmed Firefox — is already shaped for it.

Self-improvement loop

Beatrice + Mariah, broader scope

Today: detect misconfigured specialists, propose YAML/code edits, Jasper approves the PR. Next: detect persona drift across weeks of conversation, propose calibration. Then: detect successful patterns across users (with consent), surface them as cross-household best practices — never auto-applied, always opt-in per household.

Run it yourself

What you'd need.

Hearth is local-first by design. The vault is your data on your disk. The model runs on hardware you own. The only outbound default is Telegram (because you're the consumer).

Hardware

  • Always-on box — anything that can run Bun + SQLite + Hono. A NUC, a Pi 5, an old desktop. ~2 GB RAM headroom for Hearth itself; more if you also host the LLM here.
  • LLM host — 16+ GB VRAM for the 9B Heretic; 24+ GB for the 27B Q4. A 3090 or 4090 works; a the integrated AI accelerator's 96 GB unified memory works; Apple Silicon with ≥48 GB unified works.
  • Optional browser host — a box with a real GPU for WebGL fingerprint authenticity. Wake-on-LAN capable so it can sleep when idle.
  • Phone — for HA Companion location reporting, and for the Telegram surface.

Software stack

  • Bun (any recent version). Runtime + package manager + bundler.
  • Ollama or llama.cpp (or beellama.cpp for DFlash decode) serving an OpenAI-compatible endpoint.
  • Home Assistant — entities, calendars, location. Companion app on your phone.
  • CalDAV server — Radicale, Baikal, Nextcloud, or iCloud via tsdav.
  • SearXNG + Firecrawl — local containers for web search and fetch.
  • OSRM + Nominatim — local docker-compose stack for offline routing.
  • Mealie · Plex (Tautulli) · *arr · UniFi · MeTube — each optional; tools cleanly degrade when env vars absent.

Get started

  • git clone and bun install
  • mkdir -p ~/vault-friday/{People,Journal,Decisions,Inbox,System/Audit}
  • cp .env.example .env and set HEARTH_VAULT_ROOT
  • bun run init:vault — scaffolds the Knowledge/<Specialist>/ tree
  • bun run dev and open http://localhost:7700/app/
  • bun run smoke, bun run smoke:specialists, bun run smoke:proactive — eleven smoke suites verify the integrated system

Customization first stops

  • config/specialists/*.yaml — rename, retune, or add personas. Hot-reloaded.
  • config/policies/v0.yaml — what gets auto-approved, what queues. First-match-wins. Hot-reloaded.
  • config/llm-roles.yaml — point at any OpenAI-compatible endpoint. Per-role model swaps.
  • config/privacy.yaml — location + browse redaction, per-specialist allowlists.
  • config/autonomy.yaml — graduation thresholds per tier.
  • config/notifications.yaml — quiet hours, push severity thresholds.

The single architectural invariant: localhost-bound by default; Tailscale for remote access; never WAN-bind. The threat model is "well-meaning automation overstepping," not "external attacker." Adding auth scaffolding beyond what you've opted into is overengineering.
